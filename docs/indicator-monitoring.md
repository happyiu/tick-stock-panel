# 自建指标监控 V1

指标监控独立于行情监控，支持股票、ETF，以及30f、日线。内置图表指标、指数、周月线、动态自选分组和自动交易不在本版范围内。

## 配置与使用

1. 在“指标”页面编辑自建主图或副图，点击“添加信号”。为公式已经定义的条件变量绑定中文名称并选择适用周期。例如 `buySignal` 对应“试仓”。绘图文字、颜色、箭头不自动成为信号。
2. 最低历史根数默认为100，应按公式需要调整。条件有限且非零表示成立，零表示不成立，空值表示不可计算。持续为真的条件可在每根K线上触发一次；只需穿越事件时，在公式中使用 `CROSS`。
3. 在详情页指标菜单点击铃铛，自动带入标的、指标、周期和量能对比参数；或者在“监控中心 → 指标监控”新建。
4. 勾选信号、选择触发方式和通知渠道。相同标的、指标、周期只能有一条规则，在其中组合多个信号。

应用内记录始终启用。系统通知受全局开关控制，外部渠道须先完成既有通知设置。关闭图表或浏览器不影响后台服务；电脑休眠、后端停止时不会继续检查。

## 触发时间

- 每60秒使用最新可用数据检查，实际延迟还受供应商、网络和计算耗时影响。
- 实时预警：形成中的K线首次满足条件通知一次，同根信号消失后再次满足不重发。
- 收盘确认：时间已到且分钟数据实际覆盖完整周期，最终条件成立才通知。缺分钟、数据过期、复权未知时不能视为已确认。
- 默认两者都要。预警最终不成立时，记录显示“收盘未确认”，不另发撤销消息。
- 午休补查上午尾根，盘后补查至北京时间15:30。仍缺数据则标记“数据缺失，未能确认”。

新建、恢复或采用新版本时对已经完成的K线建立基线，不补发历史信号；当前形成中的K线可在首次检查时预警。正常重启恢复处理进度，只补确认当日漏处理的完整K线，消息标记延迟；不会补发错过的盘中预警。

## 计算一致性与版本

首次读取最近最多500根并固定实际起点，之后延长，不随可视窗口变化。历史不足时保留起点并等待补齐。超过解释器现有内存、根数或耗时上限会明确报错，不静默截断。

监控记录中的“查看图表”使用同一份输入和公式上下文；触发记录保存当时的压缩快照，修改公式或删除规则后仍能查看。普通图表的历史加载范围可能与该上下文不同，核对监控结果请从监控中心打开。

公式、信号定义、适用周期、最低历史根数改变，或数据源/复权口径改变后，相关规则停止评估。点击“采用新版本／重建上下文”明确恢复；名称和说明调整不改变计算指纹。若选中的信号被删除，先暂停规则、重新选择信号，再采用新版本。

## 存储与通知

- 规则：运行数据目录下 `user_data/indicator_monitors.json`，原子写入。
- 状态、去重、事件、压缩快照和通知待发送项：`user_data/indicator_monitor.sqlite3`，事务写入，不参与Git提交。
- 事件按规则、代次、信号、K线结束时间、预警/确认阶段唯一识别。清空记录不清空去重进度；删除规则保留触发历史。
- 历史最多保留七天、5000条。通知先保存事件，再交独立线程投递；失败重试同一事件，可在记录中手动重试失败渠道。
- 本地事件不会因重启重复生成。外部渠道成功接收但响应丢失时，重试可能重复送达，不能承诺外部严格仅送达一次。

这是L3改动：独立后台服务和API接入应用生命周期，详情页指标菜单、监控中心及指标编辑器增加交互。共享K线读取/实时日线投影与通知渠道选择，没有继承旧监控引擎。

新增规则API位于 `/api/indicator-monitors`，提供CRUD、事件查询/清除/重试、采用新版本和上下文快照；旧行情规则API及其JSONL历史保持原有行为。指标保存/查询增加可选的 `monitor_signals`、`min_history_bars`，校验返回 `variables`。旧指标无需迁移，旧调用方省略新增字段时保留现有配置。

缓存键包含标的、资产、周期、公式、参数和历史起点；每轮共享取数及相同公式计算。SSE使用指标来源精确刷新相关规则、事件和快照查询。合并上游时重点复核应用生命周期、K线共享投影、通知分发、前端API类型和监控中心标签。后台服务按现有单进程应用部署；不以多worker重复启动后台调度器。
