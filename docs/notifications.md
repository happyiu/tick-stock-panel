# 第三方推送通知

在设置 → 实时监控 → 推送通知 → 第三方系统中选择接入方式，填写接收地址和密钥，保存后点击测试。

- **通用 JSON Webhook**：沿用 `event`、`timestamp`、`title`、`body`、`data` 请求结构。可选密钥用于 HMAC-SHA256，签名位于 `X-TickFlow-Timestamp` 和 `X-TickFlow-Signature` 请求头。历史配置默认使用此模式。
- **HStudio 消息中心**：接收地址填写 HStudio Webhook 管理页面提供的完整地址；密钥填写创建或重置时显示的来源密钥，使用 `Authorization: Bearer` 鉴权。发送 `eventId`、`title`、`content`、`data`，标题及正文按接收端限制截为 100 和 16000 字符。

两种模式都应用于监控告警（含指标监控）、模拟盘成交通知和每日复盘。勾选第三方系统只设置新建规则的默认渠道，已有规则仍须独立勾选。

指标监控表单目前不自动继承全局默认渠道，需要在每条规则的“通知渠道”中勾选“自定义Webhook”。

HStudio 指标监控消息自动添加顶层 `tags: ["indicator"]`，消息中心可按“交易信号”分类筛选，并使用指标卡片展示。接收接口的字段名是 `tags` 数组，而不是单数 `tag`；其他来源消息及通用 JSON 模式保持原有结构。

指标事件的 `data.symbol_name` 为标的名称，通过仓库统一股票/ETF名称缓存解析，在触发时随事件保存。找不到名称时为空字符串，保留 `symbol` 代码展示；历史事件无需迁移。

HStudio 同一次网络重试复用事件 ID；有持久化事件 ID 的指标监控在任务重试时也复用该标识。测试消息每次发送生成新事件 ID。HTTP 2xx 表示接收端接受请求，HStudio 202 表示消息已保存，不代表手机已展示。手机通知另需有效设备绑定和接收端推送服务配置。

密钥只保存到本地凭据文件，设置响应仅返回是否已保存；留空保持原密钥，清空接收地址会删除密钥。不要把密钥写进 URL、策略或版本库。

本次接入属于 L3：修改现有设置契约和共享 Webhook 适配器。新增 `custom_webhook_protocol`，旧配置缺失时回退 `json`，无数据迁移。保存仍使用 preferences/secrets 的写入及 mtime 缓存失效，前端使共享 preferences 查询失效；不影响行情和 K 线缓存。升级上游时复核设置 API、前端类型及各通知调用方传递的协议参数。
