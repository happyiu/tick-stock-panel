# 自选标的详情：综合研判面板实施计划

状态：第一阶段、行动决策层及详情页波浪理论 v2 已实现；综合摘要 AI 与多周期服务端复用仍待实施。本文记录当前实现边界，不表示后续接口已经实现。

参考：[AI 分析方案比较](https://chatgpt.com/share/6a9d2a71-7390-83ee-92d9-2f221a736228)。

## 1. 目标与范围

在自选标的详情右栏顶部增加“综合研判”，整合技术指标、缠论、波浪、关键价位和信号风险结果，首先回答：

1. 当前技术方向与结构状态是什么？
2. 支持和反对这一判断的证据是什么？
3. 尚缺哪些条件，哪些条件会使当前候选失效？
4. 下一步应观察哪些价位和结构变化？

采用“确定性规则摘要 → 按需 AI 解释 → 多周期与服务端复用”的顺序交付。

第一阶段不新增综合加权总分，不新增指标算法，不改变缠论候选定义，不自动执行交易或创建监控，不迁移历史数据。沿用当前技术分，并分别展示结构状态与观察状态。

### 2.1 详情页波浪理论 v2（当前周期）

- 先按 `asOf/selectedBarKey` 截断，再复用已闭合 Chanlun 分型；未闭合尾部最多显示 `suspected`，不进入计数。
- 候选覆盖普通推动浪、引导/终结楔形、锯齿、平台、三角形和组合结构；三角形与组合结构在端点不足时明确为 `unresolved`。
- 主计数最多一个、备选最多两个；硬规则失败淘汰候选，`unknown` 不升级为 `pass`；候选 ID、规则 ID、证据 ID 在同一快照内稳定。
- `POST /api/stock-analysis/elliott/explain` 只解释本地计数与证据引用，不能生成计数、规则、价格边界、概率或交易动作；旧 `/analyze` 接口保留兼容。
- 波浪结果只进入 summary 的方向分歧、支持/反对证据和限制说明，不参与买入、减仓、卖出门槛；多周期证据当前为 `unavailable`。

拟议输出：

```text
context            标的、周期、观察时点、价格口径、分析窗口
quality            ready / limited / blocked，附具体原因
versions           摘要规则及各输入模块版本
technical          方向、现有技术分、各维度分及覆盖率
structure          结构状态、定义口径、候选及近似限制
observation        观察 / 等待条件 / 存在分歧 / 候选失效 / 数据不足
headline           一句话状态
supportingEvidence 有利依据及来源
opposingEvidence   不利依据及来源
conflicts          可复核的分歧
conditions         尚待满足的条件及各自状态
invalidation       与具体候选绑定的失效条件
levels             引用已有价位区间
risk               引用已有结构空间与不可计算原因
limitations        数据缺口与方法限制
```

完成标准：上下文、空值、单位、版本和候选状态有明确类型定义；所有条件能追溯到真实输入。技术置信度只解释为现有算法的启发式可靠程度，不表述为上涨概率或胜率。

- [x] 实现首批分歧：趋势与动能方向相反、趋势与有效结构候选方向相反、本地波浪与缠论方向相反。

- [x] 摘要主结论最多一条、主要依据最多三条，其余放入详细依据。
- [x] 全局摘要由完整候选集合确定；用户点选候选只切换局部风险详情，不改变总体方向。

规则约束：

- 缺失项不替换为 0 分或中性；关键上下文冲突时阻止生成综合结论。
- 过期快照可以继续展示，但明确其时点与过期状态；当前周期数据未就绪时不能使用其他周期顶替。
- 未闭合 K 线的数据标记为形成中，不将其用于升级确认状态。
- 缠论低级别递归缺失时，始终保留候选／等待，技术分不能将其升级为严格买卖点。
- 失效条件必须绑定具体候选；支撑区下沿不能自动替代所有候选的失效边界。
- 风险收益只表示当前参考价格下的结构空间，不解释为已成交收益或胜率。
- 新增任何“放量”“有效突破”条件前，先明确公式、窗口、闭合要求和适用周期，并补测试。

完成标准：同一输入和规则版本生成完全相同的结构化结果；每句模板结论都有可查证据。

## 3.5 行动决策层：当前周期双结论

行动层继续消费 `stockSummary` 的确定性输入，不新增请求、API、持久化或综合加权总分。它把同一份证据分别翻译成“未持有”和“已持有”两种视角：

- 状态固定为 `buy / probe / wait / reduce / sell`，判定优先级为卖出、减仓、买入、试仓、等待。
- 买入只允许二买/三买候选在低级别确认、技术四项均不低于 60、结构空间至少 1:2 且无分歧时成立；低级别确认缺失时最多为试仓。
- 卖出要求卖侧候选、低级别确认、技术四项均不高于 40、结构偏空且无分歧；当前代理结构缺少低级别递归时，卖侧最多降为减仓。
- 一买、等待回抽、候选失效/拒绝、技术与结构冲突、风险空间不可计算均保持等待。
- 缺 K 线、评分或结构时为 `blocked`；过期快照或未闭合 K 线为 `provisional`，不升级行动状态。波浪不可用只进入限制说明。
- 图表展示源失败但 API 已明确回退到本地 `enriched` 且末根 K 线已闭合时，摘要标记为“部分可用”并保留回退限制，不把回退数据误判成过期展示快照；真正的 `chart` 过期快照仍按 `provisional` 处理。
- 顶部同时展示行动结论、升级条件、风险/失效观察和当前价/支撑/压力/候选边界；支撑压力只作观察区，不自动作为触发器。

该层是可追溯的技术研究结果，不是自动交易指令，不提供仓位百分比。当前只使用选中周期；多周期共振仍属于第三阶段，需先完成统一观察时点和低级别数据对齐。

接口定位：这是对经过校验的客户端展示快照进行解释，不把客户端提交结果认定为服务端权威交易信号。已有个股四维 AI 分析继续保留，避免其最新日线数据与当前历史／周期上下文混用。

第二阶段完成标志：AI 失败不影响规则摘要，解读可以追溯到指定快照，不修改程序生成的分数、价位及候选状态。

## 5. 第三阶段：多周期与服务端复用

作为后续独立任务实施，前两阶段不依赖本阶段。

- [ ] 复用现有多周期查询，显式开启后才加载，未加载显示“未评估”。
- [ ] 先补齐分钟、日、周、月数据的统一观察截止时间与闭合处理；历史时点不得读取之后才完整形成的高周期数据。
- [ ] 先输出各周期状态与一致／分歧矩阵，不将多周期指标一致称为严格缠论递归确认。
- [ ] 若需要批量扫描、监控或回测，逐步把结构及摘要算法迁入后端领域服务。
- [ ] 用固定样本验证迁移前后的结构、价位、信号及摘要一致；切换消费者后删除被替代的计算实现，避免长期维护两套权威算法。
- [ ] 需要历史对照时再设计快照存储、版本、失效与读取兼容；不提前修改行情 Parquet schema。
- [ ] 回测另行验证信号可获得时间、成交时间、资产交易约束和未来数据隔离。

完成标志：多周期证据严格对齐观察时点；服务端扫描与详情消费同一计算结果。只有实际通过回测验证后，才宣称支持可回测信号。

## 6. 交付顺序与改动纪律

```text
P1-1 输入与规则契约
  → P1-2 纯函数与规则测试
  → P1-3 面板和联动
  → P1-4 回归与界面验收
  → 第二阶段 AI 解读
  → 第三阶段多周期及服务端复用
```

- 每个阶段独立验收，不以“页面能打开”作为完成标准。
- 开始代码实施前重新检查工作区、根目录规范及实际调用链。
- 第一阶段主要修改前端，保留现有数据、API 和评分口径；如发现上游契约问题，先明确最小修复范围。
- AI 缓存与规则快照分离；页面只接受与当前上下文一致的有效结果。
- 不覆盖已有修改，不自动提交、推送或合并。
- 交付报告列出实际修改文件、真实执行的测试结果、界面证据及未验证风险。
